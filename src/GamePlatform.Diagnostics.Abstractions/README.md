# GamePlatform.Diagnostics.Abstractions

Owns the BCL-only diagnostics boundary. `IAppLog` and `NullAppLog` remain source compatible. `SafeAppLog` adds an enabled check, code-defined category/event symbols, a deferred field factory, captured process-local correlation/generation and immutable sanitized records for an injected `IStructuredAppLogSink`. No framework or output adapter is installed. Relevant gate: A12 (SDK unit evidence only; Unity output is INT-004).

Use code-defined symbols (ASCII letters/digits/dot/underscore/hyphen, at most 64 characters), never identifiers or user text, for category/event/field names. Invalid metadata drops the event or field. At most 16 source entries are inspected; arbitrary strings, objects, non-finite numbers and unknown-named scalar fields become `[redacted]`. Numeric/boolean/null values are accepted only for the case-sensitive metric names `count`, `attempt`, `attemptCount`, `durationMs`, `elapsedMs`, `bytes`, `byteCount`, `queueDepth`, `statusCode`, `errorCode`, `retryable`, `ok`, `revision`, `sequence` and `nothing`. Values must themselves be non-personal measurements; do not smuggle identifiers into metric fields. Exceptions produce only `HasException`; messages/stacks and raw exception objects never reach the sink. Do not put secrets into metadata or correlation: correlation is an opaque process-local identifier, not a provider/player ID. Duplicate field names use the last inspected value; null/throwing factories or enumerators drop the event.

Construct one immutable `AppLogContext` per captured scope. Deferred delivery retains the original correlation and generation, even after account replacement. Fields are copied into a read-only dictionary. Sink/enabled/factory/enumerator failures are swallowed without recursive logging; no diagnostic outcome may control transaction success. `SafeAppLog` borrows its sink, owns no worker or queue and does not dispose it. Sinks must return promptly; any future asynchronous adapter must impose its own bounded queue/drop policy. No allocation/performance claims are made.

The original `IAppLog` interface itself cannot enforce safe behavior on arbitrary third-party implementations. Inject `SafeAppLog` (or the null implementation) into business services, rather than a raw output adapter. The legacy eager overload uses category `Legacy`; new calls should use the deferred overload to avoid work when disabled. Rollback can substitute the null sink without changing business state or persistence.
